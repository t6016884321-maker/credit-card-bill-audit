# 账单 PDF 模板适配指南与四个真实解析陷阱

## 1. 为什么必须用坐标解析

PDF 的文本流顺序 ≠ 表格阅读顺序。直接按 `get_text()` 的换行切分，
会把「标签」和「金额」错行配对，尤其是跨页表格、双币种并列行、页脚提示行。

本 skill 用 `pymupdf` 的 `page.get_text("words")`，按 `y0` 容差 2.6pt 聚成行，
再按 `x0` 排序，最后**按列的 x 坐标区间**取金额。做新银行适配时，
第一步永远是 `profile_statements.py` 输出的金额列 x1 聚类。

## 2. 配置文件字段（`assets/profiles/*.json`）

| 字段 | 说明 |
|---|---|
| `date_re` | 交易/入账日期的正则，如 `^\d{4}/\d{2}/\d{2}$` |
| `base_currency` / `currencies` | 主口径币种与合法币种列表 |
| `non_money_units` | 非货币单位（积分、里程），命中即丢弃该行 |
| `deposit_marker` | 溢缴存款标记（「存款」），用于识别负余额 |
| `markers.txn_all` / `txn_any` | 进入交易明细区块的关键词 |
| `markers.summary_any` | 进入勾稽式区块的关键词 |
| `markers.installment_any` | 分期明细区块 |
| `markers.stop_any` | 退出区块（温馨提示、积分汇总、校验码、广告等） |
| `columns.trade_x1` / `post_x1` | 交易金额 / 入账金额的**右边界 x1 区间** |
| `columns.currency_x0_min` | 最右侧货币列的 x0 下界 |
| `columns.summary_x0_max` | 摘要文字的 x0 上界，右侧内容不进摘要 |
| `columns.account.*` | 首页账户信息区的列边界 |
| `summary.*` | 勾稽式行的币种列位置、最少金额数、取最后 N 个金额 |
| `infer_columns` | 为 true 时自动聚类推断列边界 |

## 3. 四个真实踩过的坑（每个都曾让总账差钱）

### 坑 1：积分被当成钱

账单里有形如 `境外促销活动赠积分 -48,000.00 积分`、
`生日当月双倍积分奖励 -1,900.00 积分` 的行（此处为示意数值）。
它们的**金额列格式与人民币完全一致**，但入账货币列写的是「积分」。

后果：累计余额一次性差数万元 / 数千元。
处理：取 `x0 > currency_x0_min` 的最右列，若其值不在合法 `currencies` 里，整行丢弃；
并额外检查行文本中的 `non_money_units`。

### 坑 2：外币混入本币

同一期账单的勾稽表可能人民币、美元分两行并列：

```
人民币   10,000.00    3,000.00   2,000.00   11,000.00
美元        120.00       30.00      50.00      100.00
```

后果：把美元入账金额加进人民币口径，逐笔合计与勾稽式差一笔。
处理：`summary` 行按 `currency_x0_max` 左侧的币种词标注；主口径只取 `base_currency` 行；
外币交易单独保留在 `transactions.csv`，**不折算、不估汇率**。

### 坑 3：「无欠款」不是 0

账户信息区显示「无欠款」时，同一行往往还有「存款 500.00」/「存款 2,000.00」字段，
表示**银行欠持卡人**的溢缴款，真实余额应为负数。

后果：记成 0 会让本期与下一期各差一个存款金额。
处理：优先用勾稽表的 `500.00（存款）` 解析为 `-500.00`；
没有勾稽表时，用 `deposit` 字段取负；只有确无存款时才记 0。

### 坑 4：分期冲帐不是提前结清

`账单分期冲帐 -12,000.00` 这类负数行通常出现在分期**成立**时，
用于冲回原消费，避免同一笔消费被计两次。它不是提前结清，也不是退货退款。

后果：误判为退款会虚增退货金额、扭曲净消费，误判为提前结清会引出错误的质询。
处理：保持原分类（`其他冲账`），在 issue 里标为「需银行说明业务类型」，不自动定性。

## 4. 其他模板差异

| 差异 | 表现 | 处理 |
|---|---|---|
| 无文本层（扫描件） | `get_text()` 几乎为空 | 先 OCR（`ocrmypdf`），坐标解析才可用 |
| 加密 PDF | `needs_pass=True` | 向银行索取无密码原件，或在本地合法解密后再解析；不要把密码写进配置 |
| 交易跨页 | 第 1 页末尾 + 第 2 页开头 | 区块状态 `mode` 跨页保持，遇 `stop_any` 才退出 |
| 勾稽表位置变化 | 与交易明细同页 / 单独页 | 不按页号定位，按关键词切区块 |
| 附加页 | 分期明细、积分汇总、营销页 | `stop_any` 命中后停止解析，避免把广告数字当交易 |
| 早期账单无勾稽表 | 只有账户信息区 | `formula_diff` 留空，靠 V3/V5 累计闭合兜底；不要硬填 0 |
| 空账期 | 一期无任何交易 | 正常期次，不算缺月；`txn_count=0` |
| 名目跨年改名 | 「分期手续费」→「分期利息」 | 分类规则同时兼容，按合同**成立日**而非改名日适用规则 |

## 5. 新银行适配流程（务必按顺序）

1. `fetch_bills.py` 下载全部 PDF，确认 `manifest.csv` 期次连续。
2. `profile_statements.py --out <dir>` 查看 `profile_suggestion.json`。
3. 复制 `cgb_classic_platinum.json` 或 `generic.json`，填入列边界、日期格式、区块关键词。
4. 挑**首期 / 中期 / 末期** 3 份 PDF，用 `parse_statements.py --limit 3` 试解析，
   人工比对 `transactions.csv` 与 PDF 原件的前 10 行。
5. 全量解析 → `validate_ledger.py`。**只要有一项 FAIL，就回去改配置，不要调容差蒙混过关。**
6. 常见失败原因对照：
   - V3 大面积差异 → 金额列区间取错，或漏掉了某个交易区块；
   - 差一个固定金额 → 积分行 / 外币行混入；
   - 只有 1–2 期差 → 「无欠款」的溢缴款或跨页表头重复；
   - V1 缺月 → 银行确未补寄，向银行索取，或经用户确认后加 `--allow-missing-periods` 并在报告注明。

## 6. 已验证配置说明

`assets/profiles/cgb_classic_platinum.json` 来自一次覆盖十余年、192 期、
近 6,000 笔交易的完整实测：逐期余额、逐笔对勾稽表、跨期衔接、全期累计**零差异**。
它证明这套坐标解析方法可行，但**坐标是 PDF 点数，换银行必然不同**，
请把它当作格式范例而不是通用配置。

# 两份报告的章节规范与可核验性要求

生成逻辑在 `scripts/build_reports.py`，样式在 `assets/report.css`。
**所有数字从 JSON/CSV 实时读取，禁止在模板里硬编码金额。**

## 报告 1：期间用卡情况分析与总结（用户自用）

| 章节 | 必备内容 | 数据来源 |
|---|---|---|
| 封面 | 银行名、账期范围、期数、出具日期、四个能力标签 | `analysis.json` |
| KPI 卡片 | 毛消费、息费、经济总支出、实际还款、净年费、累计利息 | `analysis.totals` |

| 二 数据可靠性 | 闭合等式 + V1–V7 七项校验表 | `validation.json` |
| 三 五个口径 | 毛消费 / 净消费 / 息费 / 经济总支出 / 实际还款 / 期末未还 | `analysis.totals` |
| 四 年度趋势 | **独立刻度双柱状图** + 年度表（含合计行） | `analysis.year_rows` |
| 五 消费与资金结构 | 分类笔数、金额、占净消费比 | `category_summary.csv` |

| 八 用卡行为与利息成因 | 有欠款期数占比、还款期数、隐含日利率异常期数 | `behaviour` / `interest_diagnostics` |
| 九 问题清单 | C01–C18，状态徽章 + 证据强度 + 不得引用清单 | `findings.json` |
| 十 **明明白白用卡改进清单** | 8 条可执行动作：全额还款、关闭自动分期、看年化、积分规则、定期查账、索要发票、留痕、不找中介 | 静态文本 + 数据提示 |
| 十一 时效与现实预期 | 切分点、时效内/外息费、可直接认定金额 | `statute` / `findings` |
| 附录 | 可核验文件目录 | 固定清单 |
| 页脚 | 非法律意见声明 | 静态 |

### 图表规范

- 净消费与息费**必须使用两个独立刻度**的上下双面板；共用刻度时息费柱几乎不可见。
- 标题、最大值、年份标签齐全；年份标签抽稀避免重叠。
- 首年/末年若非完整年度，图注明确说明。

## 报告 2：致银行书面异议、索证及权利主张函（可直接发送）

| 章节 | 必备内容 |
|---|---|
| 抬头 | 收件部门、投诉人/证件号/卡号后四位/联系方式**留空待填**、账期、附件 |
| 函件性质 | 四合一：消费投诉 + 账单书面异议 + 个人信息查阅复制申请 + 发票开具申请 |
| 一 事实摘要 | 七项金额 + 可核验性声明（闭合等式、原件 SHA256、愿配合核对） |
| 二 逐条质询 | Q01–Q18 卡片：事实／线索、依据、请提供、备注；**每条单独编号答复** |
| 三 发票专项 | 按费用类型列金额 + 合计 + 分段税目 + 不得拒开的理由 + 12366 |
| 四 权利清单 | 26 项：权利 / 依据 / 本次如何行使 |
| 五 三层主张 | A 可直接主张（无则 0 元）/ B 条件性 / C 协商性 |
| 六 时限与升级 | 15 日书面答复、6 级升级路径、证据保全、时效中断 |
| 七 证据目录 | E01–E07 |
| 八 不得引用的说法 | 被证伪/已废止清单，**主动排除**以建立可信度 |
| 九 签署 | 签名、日期、联系电话、银行投诉编号栏 |
| 发出前须知 | 填字段、核金额、可留痕渠道、律师复核、法规复核 |
| 页脚 | 非法律意见声明 |

## 可核验性要求（硬性）

1. 报告中每个金额都能在 `transactions.csv` 逐笔加总复现；
   `balance_walk.csv` 提供逐期余额推导。
2. 逐笔明细保留 `period / page / line_no / raw_line`，可回查 PDF 原件。
3. 利息名目若存在包含关系，注明「不重复加总」。
4. 「疑似重复」「隐含利率偏高」一律写成待核实线索，不写成已认定违规。
5. 对银行有利的事实（未检出项、已整改事实）必须出现在报告里。
6. `do_not_cite` 的说法一条都不出现在正文主张中（第八章作为「已排除」列出除外）。
7. HTML 原件与 PDF 同时保留，便于用户补填个人信息后重新打印。
8. 不在函件里嵌入完整卡号、身份证号或邮箱授权码等敏感信息。

## 版式要求

- A4、17mm 上下 / 15mm 左右页边距；表格 `thead` 跨页重复。
- 中文字体栈：PingFang SC / Hiragino Sans GB / Microsoft YaHei / Noto Sans CJK SC。
- Q 卡片 `page-break-inside: avoid`，避免一张卡片跨页。
- 生成后检查：无空白页、无 `file://` 页眉、无浏览器日期戳、无未替换占位符、无 HTML 实体泄漏。
